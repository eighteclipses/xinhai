## 01　为什么做这件事

喜欢 Persona 的人，大概会记得一种很特别的感觉：白天上课、读书、和人交谈，看起来只是平常的一天，到了夜里回头看，却发现自己已经多懂了一点，也多了一点向前走的力量。

心海共学想把这种感觉带回电脑前。它把专注计时、待办、习惯、日记和个人知识库放进一个有音乐、有场景、有成长反馈的桌面空间。打开它之后，不需要先想好一套复杂的自律计划。写下一件今天愿意完成的小事，就可以开始。

这份作品最在意的，不是让用户不断刷新数字，而是让“我今天做过什么”能够被看见。一段专注会留下记录，读懂的内容可以整理成笔记，容易忘记的知识可以做成复习卡。习惯断了一天，也仍然可以回来继续。

它是一件持续打磨中的非官方同人作品。Persona 的角色、视觉语汇和日常成长体验是重要灵感；项目自身的工作主要在于桌面软件实现、学习流程组织、五维反馈设计，以及界面、音频和数据之间的衔接。使用的游戏片段、角色素材、音乐及其他第三方内容，按照实际来源记录鸣谢，不将其描述为项目从零创作的素材。

## 02　项目定位与适用场景

**一句话定义：**以 P3R 氛围为灵感，围绕“开始行动—保持专注—整理知识—回看积累”组织的本地学习陪伴工具。

### 适合谁

- 喜欢 Persona，希望学习桌面有一点熟悉氛围的用户。
- 需要番茄钟、任务清单、习惯记录，又不希望在多个工具间频繁切换的学生与自学者。
- 已经使用 Markdown 或 Obsidian，希望在专注时顺手整理笔记与复习内容的人。
- 更愿意把学习资料保存在自己电脑上，并自行选择是否接入云模型服务的人。

### 三条设计原则

**先让人愿意开始。** 首页承接当前任务、专注入口和当天记录。待办建议提供的是一个能动手的小目标，而不是宏大的计划口号。

**反馈跟着行动走。** 专注和打卡完成后产生记录，再进入对应的成长反馈。音符、五维图形和等级称号承担表达作用，准确的原始数据保留在后台与导出中。

**工具应当能够安静下来。** 音乐与导航收在底部，背景、人物和面板可以调整；用户可以降低动态效果，也可以隐藏界面，保留陪伴空间。

### 当前边界

本项目不是多人协作平台，也不是云端学习管理系统。0.1.9 的交付重点是 Windows 本地使用；目前没有账户体系、跨设备同步、移动端安装包、排行榜或付费订阅。文档中的成长概念用于表达个人行动记录，不代表经过心理测量验证的能力评估。

## 03　从一件小事开始的使用流程

1. **写下任务。** 在待办中添加一个明确目标，例如“复习五道错题”，选择优先级与计划日期。
2. **进入专注。** 从任务卡片开始计时，任务名称会带入专注页；也可以直接输入临时目标。
3. **完成并保存。** 计时结束后保存本次实际专注时长，展示完成反馈，再查看五维成长。
4. **整理学到的内容。** 在知识库中记录理解、例子和疑问，将容易遗忘的内容制作成复习卡。
5. **下一次回来。** 查看到期复习卡、继续习惯打卡，或在日历里回看完成过的事。

一个任务不要求在一轮专注内结束。与任务关联的专注时间可以累计，任务是否完成仍由用户自己决定。这个分工让“投入过时间”和“完成了目标”分别有清楚的含义。

## 04　功能说明

### 4.1 共学桌面

首页展示本地日期与时间、当天的学习状态、待处理任务和近期安排。用户可以从这里选择下一件事并进入专注，避免一打开软件就面对大量设置。背景音乐与场景贯穿各个功能页面，切换工具时仍保留空间的连续感。

### 4.2 专注计时与完成反馈

支持常用番茄钟预设、自定义专注与休息时长，以及手动结束的正计时模式。暂停期间不累计有效专注时间；页面切换后，正在进行的计时继续保持。

计时实现采用单调时钟计算经过时间，而不是单纯依赖界面每秒刷新次数。保存时将专注记录、成长结果与关联任务的投入时间放入同一数据库事务，并使用提交标识避免重复点击或重试导致重复入账。

完成演出结束后会停留在定格画面，用户点击“查看成长”或按 Esc 后继续。原总攻击片段的声音已移除，避免与用户正在听的音乐叠加。降低动态效果或视频不可用时，也有静态画面承接。

### 4.3 待办事项

待办包含标题、优先级、计划日期、预计番茄轮次的基础数据，以及完成状态和已关联的专注时间。当前界面提供待完成、今天、已完成与全部筛选，并汇总今日计划、待完成和需要重新安排的任务数量。

完成日期与计划日期分别保存。日历据此区分“原计划哪天做”和“实际哪天完成”。较早版本没有保存实际完成日期的历史任务，不会被随意计入某一天的完成记录。

### 4.4 习惯与历史记录

用户可以创建习惯、指定对应成长维度并按天打卡。同一个习惯当天重复请求不会重复加分。界面展示近期打卡情况，点击连续天数可展开最近 30 天记录。

0.1.9 新增卡片拖动排序与删除：按住左侧手柄上下调整，松开后保存；键盘聚焦手柄后也可使用方向键。删除会移出活动列表，并提供撤销。历史打卡和已经产生的成长记录保留，避免删掉一个习惯就丢失过去的积累。删除所有习惯后重新启动，也不会强行恢复默认列表。

### 4.5 日历与活动回看

日历整合五类信息：待办、习惯、日记、专注和自定义安排。月历上的标记帮助用户判断哪天留下了记录，右侧展示所选日期的具体事项。

日期按本地时间解释。跨日完成的专注按结束日期呈现；历史任务缺少实际完成时间时明确保留其边界。日历直接按月份查询数据库，不依赖某个页面最近加载的少量记录，因此不会因为列表截断而漏掉较早的活动。

### 4.6 个人知识库与 Obsidian 配合

知识库直接读写用户选择的 Markdown 文件夹，笔记不必先转换成专属格式。可以选择已有的学习资料目录或 Obsidian 仓库，在软件内浏览、编辑和创建笔记，并通过入口返回文件夹或 Obsidian。

保存时带有内容版本校验。文件在外部被修改后，软件会阻止旧内容直接覆盖新内容，降低多个编辑器同时使用造成的误覆盖风险。路径校验限制笔记读写范围；符号链接、过深目录及超限文件会被跳过或拒绝。

当前提供的是围绕 Markdown 文件的学习工作区，不承诺完整复现 Obsidian 的插件、复杂双链语法、附件预览或全部编辑体验。

### 4.7 复习卡与间隔安排

复习卡位于知识库内，包含问题、答案、科目与可选的来源笔记。可以手动创建，也可以选中笔记正文后制作卡片。复习时先显示问题，用户主动翻开答案，再按记忆情况安排下次出现的日期。

排期使用清楚、可解释的规则：需要重学时次日再见；熟悉时延长到至少 3 天；记住时延长到至少 7 天，后续间隔上限为 90 天。这是轻量间隔复习实现，并非 FSRS 或完整 SM-2 算法。卡片保存、复习记录和排期更新均有版本及重复请求校验。

复习行为不额外直接奖励成长点数。它服务于知识保留，避免把反复点击评级按钮变成刷分入口。

### 4.8 日记与五维反馈

五个维度分别是学识、意志、表达、体贴与灵巧。日记评分优先关注明确的行为证据，而不是文字长短或情绪强弱。云模型连接由用户自行配置；未配置或服务不可用时，使用本地规则提供兜底结果。

评分结果需要由用户检查与确认，不能视作客观能力结论。本地关键词规则难以准确理解全部语境，云模型也可能误判；这些局限应在使用和展示中如实保留。

| 维度 | 主要观察的行为 | 示例 |
|---|---|---|
| 学识 | 有投入或收获的学习 | 弄懂一个概念、完成复习并纠正错误 |
| 意志 | 面对阻力仍采取行动 | 克服拖延、状态不佳时仍开始小任务 |
| 表达 | 实际输出与沟通 | 讲题、演讲、写成结构清晰的总结 |
| 体贴 | 帮助他人与合理照顾自己 | 陪伴、感谢、休息与恢复 |
| 灵巧 | 动手练习与解决问题 | 编程、绘画、实验、乐器或训练 |

界面主要使用音符数量、定性描述、等级称号与五维图形表达反馈。后台保留准确数值及来源，供审计与主动导出使用。视觉上的弱化不等于数据加密，也不意味着用户无法查看自己的原始记录。

### 4.9 音乐、背景与角色表现

播放器支持歌单展开、搜索、选曲、顺序／单曲／随机模式、进度调整和音量控制。可以导入 MP3、OGG、WAV、FLAC、M4A、AAC 和 OPUS，音乐复制到本机应用目录，重复文件通过摘要识别。移除导入条目不会删除用户原始文件。

场景包含电车、教室与其他主题背景，支持用户导入图片或视频。人物是否显示、表现形式、大小、透明度，以及面板透明度、模糊和背景暗化均可调整。对于背景中已有角色的画面，自动模式尽量避免再叠加一个人物。

教室循环由已有原片整理并处理首尾衔接，保留原始画幅与画面内已有元素。项目实现了播放、衔接和界面适配，不把素材本身描述为原创拍摄或原创三维动画。

### 4.10 留给特定日子的内容

软件包含一个每年特定日期出现的小彩蛋。它会避开专注与结算，收下后当年不再重复出现。对外介绍只保留这个提示，让使用者自己遇见它。

## 05　视觉与交互设计

### 统一的视觉语言

深蓝色构成空间底色，亮蓝承担主要操作与反馈，倾斜切面、编号、英文字标和细线用于建立 Persona 风格的节奏。五个成长维度拥有各自的辅助色，但具体任务和笔记仍优先保证阅读清晰。

### 将舞台与工具放在一起

场景是持续存在的背景，工具是进入这一空间时可以使用的层。音乐和导航保持稳定位置，首页、专注、知识库等模块通过统一的编号与过渡连接。用户不需要每换一个页面就重新寻找基础操作。

### 动画要有开始，也要有结束

成长反馈由音符引入、维度强调、等级表现和离场组成；圆环、扇区与图形变化服务于“这次影响了哪一面”。退出动作在手动跳过、自动结束与减少动态等不同路径下保持完整，并清理音效与计时器。

完成反馈保留用户的继续操作，避免在还没看清时自动离开。动画加载失败时仍能继续使用，动态表现不能成为阻挡数据保存或基本操作的条件。

### 针对真实桌面使用做减法

底部导航约 42 像素高，播放器约 48 像素高；缩减的是竖向占用。界面按常见桌面窗口调整，已经检查 1100×700 与 1440×900 等尺寸。触屏和不同系统缩放下仍有继续完善空间，不将当前桌面适配等同于已经交付平板应用。

## 06　技术架构

应用基于 Electron、React、TypeScript、Vite、Zustand 与 SQLite。架构将系统权限、文件读写与数据库操作放在主进程；渲染进程负责界面、计时交互、状态呈现与动画；预加载层提供明确的 IPC 接口。

**数据流：用户操作 → React 页面 → 预加载 API → 主进程业务逻辑 → SQLite／Markdown／媒体文件 → 返回状态 → 界面与成长反馈。**

| 层次 | 主要职责 | 采用方式 |
|---|---|---|
| 渲染层 | 页面、交互、动画、音乐控制 | React 18、TypeScript、Framer Motion、Zustand |
| 接口层 | 暴露受控调用入口 | Electron preload、contextBridge、IPC |
| 业务层 | 专注提交、打卡、排期、评分与导入 | TypeScript 主进程模块 |
| 结构化存储 | 成长、任务、记录、设置 | better-sqlite3，SQLite WAL 模式 |
| 内容与媒体 | 笔记、导入音乐、自定义背景 | 本地文件系统；Markdown 文本与媒体文件 |
| 构建交付 | 普通版／自用版编译与 Windows 安装包 | electron-vite、electron-builder、NSIS |

### 可靠性设计

- **事务提交：**专注保存与成长入账共同成功或共同回滚。
- **请求幂等：**专注提交标识、当天习惯检查和复习请求标识减少重复写入。
- **版本校验：**复习卡与笔记保存拒绝过期版本覆盖。
- **结构迁移：**新增排序、删除标记、实际完成时间等字段时兼容已有数据库。
- **渐进降级：**视频失败使用静帧、降低动态直接展示可操作结果、接口错误保留重试入口。
- **本地日期：**日历、打卡与复习按照本地日历日期处理，复习跨月与闰年边界经过检查。

这些措施针对已经实现的主要流程，不代表项目经过了全面的安全审计、所有设备兼容性认证或大规模用户验证。

## 07　数据、网络与隐私

### 哪些内容保存在本机

SQLite 保存用户设置、五维数据、成长事件、专注记录、待办、习惯、日记、日历安排、复习卡及相关记录。Markdown 笔记位于用户选择的文件夹，导入的音乐与背景保存在本地应用目录。

普通版与自用版采用不同的应用数据目录，以避免演出预览与个人学习记录相互混用。兼容旧版本时，内部目录可能沿用历史名称；界面对外统一显示“心海共学”。

### 哪些操作会使用网络

基础的专注、待办、习惯、日历、笔记与本地音乐可以离线使用。用户主动配置云模型后，日记评分会把相关日记文本发送到该服务；“测试 API 连接”只验证连接情况，不提交个人日记。点击鸣谢、GitHub 等外部链接会打开相应网站。

模型地址、模型名与密钥由用户配置。当前版本应按普通本地应用保护配置文件，不能把本地保存理解为硬件级密钥保险箱或端到端加密存储。分享排错文件、数据库或截图之前，应自行检查其中是否包含密钥与私人内容。

### 导出与备份

现有导出支持结构化 JSON 与成长 CSV，便于主动保存和分析。JSON 包含复习卡与复习记录，但不会将导入的音乐文件一并打包。当前尚未提供完整的一键备份恢复流程。需要保留完整使用环境时，应同时备份应用数据目录、Markdown 仓库和必要媒体；不要把一次 JSON 导出当成全部文件的完整镜像。

## 08　安装与首次使用

### 安装

普通版附件名为 `xinhai-0.1.9-setup.exe`，约 398 MiB。包内已包含运行所需资源，不需要用户安装 Node.js、配置开发环境或另行构建源码。它是 Windows 安装包，当前未提供 macOS、Linux 或移动系统安装程序，也尚未进行代码签名。

安装前先正常退出旧版。免安装方式需要保留完整解压目录，不能只复制其中一个 exe。首次打开后，可以先创建一个小任务、完成一次短专注，再按个人偏好调整音乐、背景和知识库目录。

### 版本区分

| 版本 | 显示名称 | 用途 |
|---|---|---|
| 普通版 | 心海共学 | 日常使用，不显示演出预览入口 |
| 自用版 | 心海共学 · 自用 | 作者自用与演出验证，保留预览入口 |

### 下载与仓库的关系

当前安装包发布在私有源码仓库的 Releases，只有具备权限的账号可以访问。公开展示仓库用于介绍项目、展示截图、记录版本方向和收集反馈；它不会自动赋予观众访问私有安装包的权限。

源码仓库暂不含完整第三方媒体，仅克隆源码还不能直接构建完整应用。安装包已经包含运行资源，两者的用途应明确区分。

## 09　验证情况与已知限制

0.1.9 及前序迭代已围绕主要使用流程完成类型检查、构建、数据库与界面检查，并在独立测试档案中验证，避免污染作者个人数据。

| 范围 | 已验证的行为 |
|---|---|
| 专注 | 真实 60 秒计时、保存、完成定格、手动继续、成长与时长展示 |
| 成长 | 音符层级、五维变化、等级表现、退出与减少动态路径 |
| 习惯 | 实际指针拖动、键盘排序、顺序持久化、删除／撤销与历史保留 |
| 复习 | 卡片读写、到期安排、重复请求、过期版本、事务回滚与来源跳转 |
| 知识库 | 笔记创建、选段制卡、回看来源与保存版本检查 |
| 音乐 | 解码、切曲、暂停继续、导入去重、后台连续播放与进度调整 |
| 日历 | 月份查询、多类记录、历史日期与实际完成日期处理 |
| 打包 | 普通版与自用版区分、资源可用、原生 SQLite 与打包运行检查 |

### 需要继续改进的部分

1. 完整备份与恢复尚未交付，是后续可靠性建设的优先项。
2. 部分交互使用鼠标与桌面窗口作为主要设计条件，触屏、键盘可达性与更多分辨率仍需完善。
3. 五维评分依赖规则与模型，不保证对所有日记语境一致准确；现阶段缺少大规模外部评测。
4. 复习使用简化排期规则，后续可以研究更成熟的记忆模型，但不会把计划写成已实现功能。
5. 第三方素材的具体文件对应与许可需要逐项补齐；鸣谢解决来源说明，不能替代授权。
6. 安装包尚未签名，更新与发布流程仍以手动版本交付为主，没有自动更新承诺。
7. 尚未针对长时间运行、所有显卡与音频设备做系统性的兼容性测试。

## 10　后续迭代方向

**先把日常使用做稳。** 优先处理备份恢复、错误提示、版本迁移、媒体加载失败和长时间使用中的问题。这些工作不一定最显眼，却决定用户敢不敢把自己的记录放进来。

**再把学习流程接得更顺。** 减少从任务到专注、从笔记到复习的多余操作；让日历回看能够更方便地找到原始内容。功能增加应围绕这条主线，而不是不断增加主导航入口。

**把陪伴空间做得更自由。** 独立环境音混音、更多可替换素材与更完善的界面调整都是候选方向。若引入收集或装饰反馈，应避免让学习变成每天必须签到才能维持的压力。

**逐步明确公开交付边界。** 先提供清楚的项目展示和更新说明，再处理素材许可、可替代素材包与公开下载。保持对当前状态的诚实，比给出一个无法兑现的上线日期更重要。

以上为方向性规划，不构成上线时间或功能交付承诺。

## 11　素材、制作与鸣谢

Persona／女神异闻录相关角色、音乐、标识和游戏画面归各自权利人所有。项目为非官方同人学习作品，与 SEGA／ATLUS 没有官方隶属或授权背书关系。素材来源按照作者提供的《感谢名单》整理，完整条目见随附的《素材来源与鸣谢》。

项目开发使用了 AI 辅助编程与文档整理。软件录像使用独立演示档案，片中的任务、日记与学习记录用于功能说明。动画的界面组合与交互来自实际运行的软件；涉及原游戏片段的部分保持其来源属性。

视频《用心制作的p3r礼物》以实际软件交互为主要画面，并通过字幕、旁白与剪辑解释使用流程。录制包含真实的一分钟专注，压缩呈现的计时镜头标注“时间加速”；示例档案不应被理解为实际用户效果统计。

感谢提供角色、背景、音乐、界面参考与制作经验的原作者，也感谢愿意认真使用、指出问题的人。心海共学还有很多可以改好的地方；如果你愿意反馈，希望你告诉我具体卡在哪一步、用的是什么版本，以及你原本期待发生什么。
